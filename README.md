# 과제 13: 병합 정렬과 퀵 정렬의 성능 비교 및 분석

본 문서는 무작위 정수 데이터를 기반으로 **병합 정렬(Merge Sort)**과 **퀵 정렬(Quick Sort - 3가지 피벗 선택 방법)**의 숫자 비교 횟수, 실행 시간, 메모리 사용량을 측정하고 비교·분석한 보고서입니다.

---

## 1. 측정 결과 요약 및 비교

- **비교 횟수 (Comparisons)**
  - 병합 정렬은 항상 균등하게 반으로 나누어 병합하므로 데이터 크기에 비례하여 안정적이고 예측 가능한 비교 횟수를 보입니다 ($O(n \log n)$).
  - 퀵 정렬의 경우 `Median-of-Three`와 `Random` 피벗 방식이 병합 정렬과 유사하거나 더 적은 비교 횟수를 기록합니다. 반면 `First` 피벗 방식은 초기 데이터 정렬 상태에 따라 불균형한 분할이 발생하여 비교 횟수가 증가할 수 있습니다.

- **실행 시간 (Time)**
  - 퀵 정렬은 내부 루프가 단순하고 제자리 정렬(In-place Sort) 방식을 취하므로, 평균적으로 병합 정렬에 비해 실행 시간이 더 빠릅니다.
  - 병합 정렬은 매 단계마다 임시 배열로 데이터를 복사하고 다시 원본으로 옮기는 과정(`merge` 과정)에서 오버헤드가 발생하여 퀵 정렬보다 실행 시간이 상대적으로 길게 측정됩니다.

- **메모리 사용량 (Memory)**
  - **병합 정렬**: 정렬 대상 배열 크기와 동일한 임시 배열(Temporary Array, $n \times sizeof(int)$)을 필수로 요구하며, 재귀 호출 스택 메모리가 추가됩니다. 따라서 데이터 크기에 선형 비례하여 메모리 사용량이 증가합니다.
  - **퀵 정렬**: 별도의 대규모 임시 배열을 필요로 하지 않으며, 오직 재귀 호출 스택(Recursion Call Stack) 메모리만 소모하므로 메모리 사용량이 매우 적습니다 ($O(\log n)$).

---

## 2. 시간 복잡도 및 공간 복잡도 분석

| 알고리즘 | 시간 복잡도 (평균) | 시간 복잡도 (최악) | 공간 복잡도 |
| :--- | :--- | :--- | :--- |
| **Merge Sort** | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ |
| **Quick Sort (First/Random/Median3)** | $O(n \log n)$ | $O(n^2)$ (First 기준) | $O(\log n)$ |

---

## 3. 메모리 사용량 측정 및 계산 방법

본 실험에서는 원본 데이터 배열의 저장 공간은 공통 비용이므로 제외하고, 알고리즘 수행 과정에서 발생하는 **추가 보조 메모리(Auxiliary Memory)**만을 측정 및 계산하였습니다.

1. **병합 정렬 메모리 계산 기준**
   - 병합 과정에서 좌우 분할된 데이터를 병합하기 위해 동적 할당하는 **임시 배열 크기** ($n \times sizeof(int)$ Bytes)
   - 재귀 호출 단계에서 쌓이는 **콜 스택 메모리** (최대 재귀 깊이 $\times$ 스택 프레임 당 대략적 바이트 수)
   - 총 메모리 $\approx (n \times 4\text{ bytes}) + (\text{Max Depth} \times 32\text{ bytes})$

2. **퀵 정렬 메모리 계산 기준**
   - 별도의 임시 배열 없이 원소 교환(Swap)을 수행하므로 데이터 보조 공간은 0 바이트입니다.
   - 분할 및 정복을 위한 **재귀 호출 스택 메모리**만 소모됩니다.
   - 총 메모리 $\approx \text{Max Depth} \times 32\text{ bytes}$ ($O(\log n)$ 공간 복잡도 반영)
